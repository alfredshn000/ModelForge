# P1 第一个可交付：delta 写入

日期：2026-10-17 ｜ 状态：**已完成并自测通过**

---

## 一、做了什么

第一个真正「修改模型」的路径：**改一条贴图路径，写回文件**。

它的价值不在功能本身，而在于**用可测量的方式证明了三件事**：

| 断言 | 结果 |
|---|---|
| 只改目标字段 | 3,107,066 字节的模型，**只变化 59 字节（0.0019%）** |
| 结构不受损 | chunk 数仍为 14，贴图条目仍为 21 |
| 差异全部落在目标字段内 | 差异区间全部位于 `TEXS[0]` 的 256 字节路径区 |

对比 Retera 的全量重写：同一个模型它会改 304 字节（BONE 重编号），
而 HD 死亡模型会改 36,319 字节（GNDX 清零）。**差两个数量级。**

## 二、模块

```
mdxcore/
  container.py        容器：切分 / 校验 / 透传拼接
  diff.py             字节差分 + 偏移→chunk 映射
  verify.py           写入校验：确认只动了该动的字节
  ops.py              语义操作，统一返回 {chunk序号: bytes}
  chunks/
    texs.py           贴图表（268B/条，无计数字段）
    seqs.py           动画序列（132B/条）
    modl.py           模型头（372B）
tools/
  mdx.py              统一 CLI：info / tex / seq / model
  selftest.py         21 个模型的全量自测
```

### 已实现的三个操作

| 操作 | 命令 | 允许变动的范围 |
|---|---|---|
| 改贴图路径 | `mdx.py tex <f> --index 0 --path a.blp` | 该条目的 256B 路径字段 |
| 改动画区间 | `mdx.py seq <f> --index 0 --start 0 --end 1000` | 该序列的 8B 起止帧 |
| 改循环标志 | `mdx.py seq <f> --index 0 --noloop` | 该序列的 4B 标志 |
| 改模型名 | `mdx.py model <f> --name X` | MODL 的 336B name 字段 |

### API 约定

```python
mdx = load(path)                                  # 只读
replacements = rename_texture(mdx, 0, "a.blp")    # {chunk序号: 新数据}
out = rebuild(mdx, replacements)                  # 其余 chunk 原样贴回
```

**所有语义操作都遵循同一形状**：`(MdxFile, 参数…) -> {chunk 序号: bytes}`。
没有「保存整个模型」这种入口，从 API 层面杜绝全量重写。

## 六、MTLS 材质层（已实现）

### 结构要点

`MTLS` **没有计数字段**，是一串材质记录，读到块尾为止。每个材质、每个图层都以 `inclusiveSize` 开头——
这一点很关键：**可以用它安全跳过变长的动画轨道**，不必实现 AnimFlag 解析。

图层固定前缀 **28 字节，与版本无关**：

```
+0  inclusiveSize    +4  filterMode      +8  shadingFlags
+12 textureId        +16 textureAnimationId
+20 coordId          +24 alpha (f32)
```

版本门控（`ModelUtils`）：

| 字段 | 适用版本 |
|---|---|
| `shader[80]` | 900 – 1000 |
| `emissiveGain` f32 | 900, 1000, 1100, 1200 |
| fresnel（3f + f + f） | 1000, 1100, 1200 |
| **合并 HD 贴图槽** | **1100, 1200** |

### 重要发现：1100/1200 的贴图不在前缀里

Reforged HD 图层把贴图放在图层尾部的**合并槽**中，每个图层 6 个槽：

| typeIndex | 槽名 |
|---|---|
| 0 | Diffuse |
| 1 | Normal |
| 2 | ORM |
| 3 | Emissive |
| 4 | TeamColor |
| 5 | Reflections |

前缀里的 `textureId` 是**历史字段**，改了不生效。所以工具在 `>= 1100` 时会自动改 HD 槽，
并明确提示"目标是 HD 槽 Diffuse"。

安全阀：若发现 HD 槽后面还跟着变长的动画子块（槽位不能恰好铺满图层），
标记 `hd_slots_trusted = False` 并**拒绝写入**，避免坐标算错写坏数据。

### 实测

| 项 | 结果 |
|---|---|
| MTLS 解析 | 10/10 有材质的模型全部通过，共 270 个图层 |
| 改图层 alpha | 351,832 B 模型只变 **3 字节** |
| 改 HD Diffuse 槽 | 61,262 B 模型只变 **1 字节** |
| 自测 | **210 项断言全过** |

## 七、GEOA 几何动画 + 批量模式（已实现）

### GEOA 结构

做法与 MTLS 一致：**固定前缀 + `inclusiveSize` 跳过变长尾巴**。

```
+0  inclusiveSize    +4  alpha (f32)    +8  flags (u32)
+12 color (3×f32)    +24 geosetId (i32，-1 表示不绑定)
```

前缀 28 字节，版本无关。之后是 `KGAO`（透明度轨道）/ `KGAC`（颜色轨道），不解析、只跳过。

### 实测

| 改 geoset 透明度 | 3,107,066 B 模型只变 **4 字节** |

### 批量模式

```bash

## 八、PIVT 轴心点 + BPOS 绑定姿势

### PIVT 结构

极简：一串 float，**没有计数字段**，每个轴心点 12 字节。第 i 个点对应第 i 个节点。

难点不在解析，而在**"这个点是谁的"**——轴心点数组按节点声明顺序排列，要显示名字就必须按同样顺序枚举节点。

### 节点头怎么安全地走

节点记录以 `inclusiveSize` 开头，但**它不包含某些块尾部的附加字段**：

| 块 | 尾部长 | 原因 |
|---|---:|---|
| BONE | 8 | 末尾还有 `geosetId` + `geosetAnimationId` |
| EVTS | 16 | 事件对象附加字段 |
| CLID | 20 | 碰撞体附加字段 |
| ATCH / LITE / PRE2 / CORN / CAMS | 0 | 尾部字段都在 inclusiveSize 内 |

**不靠猜**：先试已知值，再遍历候选值，**只有"走完刚好等于块长"才采信**。
某个块无法自证 → 该块名字一律不显示，绝不给错名字。

### 部分映射：用 BONE 当锚点

规范顺序是 `BONE → LITE → HELP → ATCH → PREM → PRE2 → CORN → RIBB → EVTS → CAMS → CLID`
（取自 Retera `EditableModel.load`）。

BONE 永远排第一，所以**只要 BONE 块能自证，前 n 个轴心点就一定属于这 n 根骨头**，
后面其它块自证失败也不影响这一段。实测覆盖率：

| 模型 | 已命名 / 总数 |
|---|---|
| alchemy_rack / Arcane Arrow / BigBookshelf / kultiranbarracksdeath | 全部命名 |
| David | 120 / 144 |
| Lvbu | 201 / 228 |
| BotanistGarden | 88 / 134 |

未能完全命名的模型会在头部明确写出原因（哪个块无法自证、节点数与轴心点数差多少）。

### BPOS 绑定姿势（只读）

`u32 matrixCount` + 每矩阵 12 个 float（3×4 仿射，48 字节），平移在 `m[3]/m[7]/m[11]`。

只读是刻意的：写绑定姿势必须保证矩阵仍是合法仿射变换，属于结构变更。

### 交叉验证

David 的 BPOS 平移与 PIVT 坐标逐项吻合（Z = 67.315 / 74.771 / 82.228 …），
两套独立解析器互相印证——这比任何单点测试都有说服力。

### 实测

| 项 | 结果 |
|---|---|
| 改一个轴心点 | 1,855,389 B 模型只变 **5 字节** |
| 自测 | **307 项断言全过** |

## 九、GEOS 解析器 + Blender 前端 v1

### GEOS：字节级可逆，证明没有漏字段

标签化布局（Reforged）完整结构：

```

| 模型 | geoset | 顶点 | 三角 |
|---|---:|---:|---:|

### 一个计数陷阱

`TANG` 的计数是「切线条数」（每条 4 个 float），
而 `SKIN` 的计数是**字节数**（Retera 直接 `loadByteArray(in, skinLength)`）。
两者看着都是 `count`，含义不同，搞错就直接偏移一大截。

只要比对通过，输出就是字节完全相同。这既是导出，也是对"Blender 能否无损承载 WC3 几何"的实测。

### 这意味着

**Blender 编辑 → 精确写回的闭环打通了。**
改一个顶点只会动那 12 个字节，其余 4 MB 原样保留——这正是最初设计 delta 透传时要达到的效果。

### 实现方式

没有"从场景重新序列化整个模型"，而是：
1. 解析原文件的 GEOS，取出每个顶点在块内的偏移
2. 比对场景与文件，只收集**真的被移动**的顶点
3. 直接 `struct.pack_into` 覆写那 12 字节
4. 用 `check_delta` 断言差异只落在这些顶点范围内，不通过就不写出

顶点增删 / 三角增删仍被拒绝（属于结构变更），会在报告里明确说明并写出原始字节。

## 十一、骨骼与蒙皮（Blender Armature）

### 数据结构

**BONE**：每条记录 = Node 的 `inclusiveSize` 字节 + 尾部 8 字节（`geosetId` + `geosetAnimationId`）。
Node 内部前缀 96 字节：`inclusiveSize + name[80] + objectId + parentId + flags`。

父子关系很干净：`objectId` 是 0..n-1 顺序编号，`parentId` 指向 objectId，`-1` 为根。
实测 11 个模型：**0 个找不到父级、0 个 flag 异常**（全部带 `0x100` 骨骼位）。

**蒙皮**两条路径：

| 来源 | 数据 |
|---|---|
| **Reforged SKIN**（优先） | 每顶点 8 字节 = 4 个骨骼索引(u8) + 4 个权重(u8/255) |
| Legacy 矩阵组 | `GNDX` 每顶点组号 → `MTGC` 每组索引数 → `MATS` 扁平节点索引，权重均分 |

实测 10 个有骨骼的模型**全部走 SKIN**，最大影响数 4，**没有漏权重顶点**，所有索引都在骨骼范围内。

### 一个真坑：同一骨骼占多个槽位

实测 David 的某个顶点，SKIN 字节是：

```
1c 03 1c 00 | 84 75 06 00
骨骼 28,3,28,0   权重 132,117,6,0
```

**同一根骨骼（28）占了两个槽位，权重 132 + 6。**
最初按槽位逐个写进顶点组，后一次 `REPLACE` 把前一次覆盖掉，导致 451 个顶点权重不对。
修法是按 `node_index` 合并权重后再写入。

### 另一个坑：骨骼名不是合法 UTF-8

WC3 里名字是 latin-1 字节，直接交给 Blender（要求 UTF-8）会在内部查表时抛
`UnicodeDecodeError`。现在统一做 ASCII 安全化 + 重名去重（`bone_clean` / `bone_2`）。

### 校验结果

```bash
blender --background --python "blender-addon/check_skin.py" -- "test-models"
```

|---|---:|---:|---:|
| alchemy_rack | 55 | 0 | 0 |
| BigBookshelfClean | 4 | 0 | 0 |
| BotanistGarden | 88 | 0 | 0 |
| kultiranbarracks | 41 | 0 | 0 |
| kultiranbarracks_portrait | 42 | 0 | 0 |
| kultiranbarracksdeath | 154 | 0 | 0 |
| David | 120 | 0 | 0 |
| David_Portrait | 121 | 0 | 0 |
| Lvbu | 201 | 0 | 0 |
| Lvbu_Portrait | 202 | 0 | 0 |

**通过 10/11**（`Arcane Arrow` 本身没有骨骼，正确识别）。
每个顶点都核对过：Blender 里的顶点组权重与文件里的蒙皮数据一致（容差 2/255，对应 u8 量化）。

同时几何往返仍是 **11/11 通过**，说明加骨架没有影响顶点数据。

### 自测

内核层新增骨骼/蒙皮校验（孤儿骨骼、漏权重、权重和、索引越界），**348 项断言全过**。

> 顺带发现：骨骼的父级可以指向**非骨骼节点**（辅助/附着点）。
> `WeaponMagicEmitter` 就有这样一根骨骼，所以"父级找不到就是错误"这个断言是不成立的，
> 已改为只在模型完全没有其它节点块时才判定异常。

## 十二、动画导入（只读展示）

### AnimFlag 布局（源码确认）

```
tag[4]            KGTR 平移 / KGRT 旋转 / KGSC 缩放
u32 count         轨道条数
u32 interp        0=DontInterp 1=Linear 2=Hermite 3=Bezier
i32 globalSeqId   -1 表示不用全局序列
count × {
    i32 time              毫秒
    f32 value[分量数]      平移 3 / 旋转 4（四元数 x,y,z,w）/ 缩放 3
    if interp > 1:
        f32 inTan[分量数]
        f32 outTan[分量数]
}
```

**关键：切线是逐条内联的**，不是"先放完所有 value 再放切线数组"。
这一点搞错会直接偏移，而且偏移量随插值类型变化——比固定字段错位更难发现。

### 导入实现

- 时间：WC3 用毫秒，按场景 fps 换成 Blender 帧（`frame = time/1000*fps`，可为小数）
- 旋转：WC3 四元数是 `(x,y,z,w)`，Blender 是 `(w,x,y,z)`，导入时重排分量
- 插值：DontInterp→CONSTANT，Linear→LINEAR，Hermite/Bezier→BEZIER
- 骨骼朝向改为 **+Y**：Blender 骨骼的局部 Y 是骨向；WC3 静止姿态下节点局部轴与世界轴同向
  （Z-up / X-right / Y-forward），这样节点的位移/旋转可以按分量直接映射，不用做轴向换算

### Blender 5 的 Action API 变了

Blender 4.4 起 Action 改成分层槽位结构，**5.x 里 `action.fcurves` 已被移除**，报错是
`'Action' object has no attribute 'fcurves'`。新写法：

```python
slot = action.slots.new(id_type='OBJECT', name=obj.name)
layer = action.layers.new("Layer")
strip = layer.strips.new(type='KEYFRAME')
bag = strip.channelbag(slot, ensure=True)
fc = bag.fcurves.new(data_path=..., index=...)
obj.animation_data.action_slot = slot      # 绑定槽位
```

已收进 `mdx_io/bpy_compat.py`，同时兼容 4.3 及更早的 `action.fcurves`。

### 两个坑

**1. 跨模型批量导入时 Action 串了。**
上一条 `MDX_Main` 不清掉，新建同名 Action 会变成 `MDX_Main.001`，而按名字取到的还是旧那条。
现在导入前会清掉所有 `MDX_*` 动作。

**2. 帧号容差不能用固定值。**
Blender 关键帧的 `co` 是 float32，帧号到 3176 时 float32 间隔已有 ~2e-4，
固定 1e-4 容差会误报。改成跟量级挂钩：`1e-4 + |v|*2e-6`。

### 已知限制（明确说明）

- **Hermite/Bezier 的切线没有写进 Blender 的 bezier handle**。
  WC3 的 inTan/outTan 单位是「单位/毫秒」，Blender 的 handle 是「值/帧」，换算涉及缩放，
  v1 先按 BEZIER 自动手柄处理。所以**播放看起来接近，但切线不是原值**。
- 因此当前是**只读展示**：能播、能核对数据，但**不能把动画改动写回文件**。
  写回必须先解决切线换算，否则会出现"抖动"这类极难定位的问题。

## 十三、动画切线写回（A'）

### 为什么这一层最危险

WC3 的 Hermite/Bezier 切线**显式存在文件里**，单位是「数值/毫秒」的导数；
Blender 的贝塞尔手柄是曲线上的控制点，单位是「数值/帧」。两者量纲不同，
这也是 Retera 长期存在「动画抖动」问题的根源。

### 换算不是拟合，是等价变换

三次 Hermite 样条在区间 h、两端导数 m0/m1 下，等价于控制点

```
P1 = P0 + h/3·m0
P2 = P3 − h/3·m1
```

的三次贝塞尔。所以**手柄放在 1/3 间距、斜率取切线换算值**时，
Blender 画出来的曲线与 WC3 的 Hermite 曲线逐点相同。

```
slope(值/帧) = tangent(值/毫秒) × fps / 1000
```

纯函数实现放在 `mdxcore/tangents.py`（不依赖 bpy），自测直接覆盖：
**5000 组随机参数，最大往返误差 1.6e-10**。

### 一个必要的实现细节：FREE 手柄

Blender 新建关键帧的默认手柄类型是 `AUTO_CLAMPED`——它会在编辑时自己重算手柄，
把我们算出来的切线悄悄丢掉。必须 `foreach_set("handle_left_type", [0]*n)`
（0 = FREE），且推导出来的手柄位置才是文件里的切线。

### 「有没有被拖动」不能比较切线

最初的写法是「从手柄反算切线，和文件里的切线比」。结果是**什么都没动也报改动**：

| 关键帧时间 | 相邻间隔 | 反算出的切线误差 |
|---|---|---|
| 60000 ms | 33 ms（1 帧） | **1.4e-4** |
| 79333 ms | 33 ms | 3.1e-4 |

原因是关键帧时间以 float32 存成**帧号**：帧号 1440 处 float32 间隔约 1.2e-4 帧，
除以 0.26 帧的手柄间距，误差被放大 4 个量级。

正确的比法是**比较手柄坐标**，容差按坐标量级给：

```python
tol_x = 6e-8 × max(|x|, 1) × 8        # 帧号 1440 → 6.9e-4 帧
tol_y = 6e-8 × max(|y|, 1) × 8        # 数值 500  → 2.4e-4
```

导入时手柄是按下式精确摆放的，用户没拖过就只差 float32 舍入；
真的拖动一次，位移远大于这个量级。改成这个判据后，
**未修改的场景 → 0 处改动**，而拖手柄必被识别。

### 只写被改动的那一侧

拖动右手柄时不能顺带重写入切线——反算带来的 float32 噪声会让入切线字节也变。
现在左右手柄分别判定，只有被拖过的一侧才写。

### 实测（三种编辑，逐个验证差异范围）

| 编辑 | 文件变化 | 切线 |
|---|---|---|
| 关键帧整体平移（含手柄） | **1–2 字节** | 逐字节不变 ✅ |
| 只改关键帧数值 | **1–4 字节** | 不变 ✅ |
| 只拖右手柄 | **4–6 字节** | 只有 outTan 变 ✅ |

在 `kultiranbarracks`（Hermite 29 条）和 `BotanistGarden`（Hermite 4 条）上各跑三种，
**6/6 通过**。其余模型全是 Linear/DontInterp，没有切线，正确跳过。

### 限制

- **不能增删关键帧**：那会改变 AnimFlag 块长度，后面的节点记录整体移位，属于结构变更。
  检测到关键帧数变化会明确拒绝并写出原始字节。
- 只处理节点变换（KGTR/KGRT/KGSC）。材质/贴图/粒子的轨道（KMTA/KMTF/…）尚未接入。

## 十四、顶点增删（C）

### 先把三个「看起来是这样」的误解纠正掉

| 字段 | 直觉 | 实测真相 |
|---|---|---|
| `PCNT` | 每个面组的三角形数 | **索引数**（三角形 × 3）。132 个 geoset 全是 3 倍关系 |
| `GNDX` | 每顶点一个字节 | 长度**要么 0，要么等于顶点数**；很多模型是 0 |
| `MTGC/MATS` | 跟着顶点走 | 与顶点**无关**：它是「矩阵组 → 节点索引」，按 `GNDX` 引用 |

所以删顶点只需要处理：`VRTX / NRMS / PVTX / GNDX / TANG / SKIN / UVBS / PCNT`，
`MTGC/MATS` 一个字节都不用动。

### 删除：连带三角形一起丢

删掉的顶点如果还挂在三角形上，那些三角形就成了悬空引用。做法是
**丢弃所有引用它的三角形**，其余索引重映射：

```
顶点 10 被 3 个三角形引用 → 删 10
  顶点 942 → 941
  三角 748 → 745
  字节 61262 → 61187（−75 = 每顶点 57 + 每三角 6×3）
```

57 字节 = 位置 12 + 法线 12 + GNDX 1 + UV 8 + 切线 16 + 蒙皮 8。

### 新增：克隆源顶点的属性

WC3 的顶点各自带一份属性，凭空造出来的顶点**没有蒙皮权重就不会跟随骨骼**。
所以新增顶点默认克隆一个已有顶点（`--from`），只覆盖坐标：

```
顶点 942 → 943，三角数不变，字节 +57
```

悬空顶点在 MDX 里是合法的（不可见），要成面得再 `--add-tri`。

### 包围盒：故意不动

实测 11 个模型里有 **10 个把 `boundsRadius` / `min` / `max` 全写成 0**——
Reforged 根本不读这几个字段（它用 `MODL` 与 `SEQS` 的 extents）。
既然不用，就不动：少改一个字节，少一份风险。

### 校验方式变了：长度会变，但只允许 GEOS 变

顶点增删必然改变块长度，`check_delta` 的「长度不得变化」前提失效。
新增了 `check_chunk_rewrite`：

1. 写出后必须能重新解析
2. chunk 数与顺序不得变化
3. **除目标 chunk 外，每个 chunk 的数据必须逐字节相同**
4. 目标 chunk 必须真的变了

### 实测

| 操作 | 结果 |
|---|---|
| 内核：11 个模型各跑增顶点 / 删顶点 / 增三角 | **33/33 通过** |
| Blender：7 个模型各跑挤出三角形 / 删顶点 | **14/14 通过** |
| 导出文件重新导入 | 顶点数一致 |

Blender 侧实测（挤出固定 +3 顶点 / +1 面，删除固定 −1 顶点）：

| 模型 | 挤出 | 删除（连带面） |
|---|---|---|
| BigBookshelfClean | +3 / +1 | −1 / −1 |
| alchemy_rack | +3 / +1 | −1 / −1 |
| BotanistGarden | +3 / +1 | −1 / **−7** |
| kultiranbarracks | +3 / +1 | −1 / **−2** |
| kultiranbarracksdeath | +3 / +1 | −1 / −1 |
| David | +3 / +1 | −1 / −1 |
| Lvbu | +3 / +1 | −1 / **−6** |

「删 1 个顶点掉几个面」取决于该顶点被几个三角形共用，实测 1–7 个。
测试脚本的期望值按实际引用数计算，而不是想当然地写 −1。

Blender 端的重建原则同样是「**没碰的属性沿用原字节**」：按坐标匹配旧顶点，
法线 / GNDX / 切线 / 蒙皮的未改动部分原样保留；只有新增顶点才从最近的
已匹配顶点继承，蒙皮则以 Blender 顶点组为准重新量化。

### 限制

- 只支持**三角形**面组。多面组（如三角带）会拒绝，因为 `PCNT` 的分组语义要逐组维护。
- 顶点上限 65535（`PVTX` 是 u16），超出会报错。

### 几何与动画同时改

```bash
blender --background --python "blender-addon/check_mixed.py" -- <model.mdx>
```

同一份导出里既移动顶点又平移关键帧，实测 **3 字节变化**（顶点 1 字节 + 时间 2 字节），
文件长度不变，`check_chunk_rewrite` 确认只有 GEOS 与 BONE 被改。

### 一个验证方法上的教训

第一版的游戏验证样本是「复制书架自己的 1 号三角形，沿 +Z 抬 30 单位」。
文件结构完全正确：

```
顶点 942 → 945，三角 748 → 749
PCNT 2244 → 2247（= 索引数，与面索引数一致）
其余 chunk 逐字节不变
```

**但游戏里看不到任何变化。**

原因是那个三角形本身只有 1.5×5 单位、位于 z≈50–56，抬 30 之后落在 z≈80–86，
而书架的范围是 x[-22.6, 20]、y[-68, 68]、z[0.7, 157.8]——**整个埋进了模型内部**。

结论：结构校验只能证明「字节写对了」，证明不了「人眼能看见」。
用来做引擎验证的样本必须自己挑位置和尺度。

现在改成 `tools/make_geom_test.py` 生成的独立金字塔：

```bash
python tools/make_geom_test.py <model.mdx> --geoset 0 --out out/xxx.mdx
```

- 位置自动放在包围盒顶端再往上 12 单位，不会和本体重叠
- 底面 70×70、高 55，尺度上不可能看漏
- 每个面正反两遍绕序，无论引擎按哪种绕序剔除背面都至少有一面朝外
- 法线按径向给，避免整块发黑
- UV 全部克隆自同一顶点，呈纯色，不会花

实测：顶点 942 → 947、三角 748 → 760、文件 +357 字节（5×57 + 12×6）。

## 十六、关键帧增删（A）

### 记录长什么样

一条骨骼记录 = `前缀(96B) + 轨道 + 尾部(8B)`，`inclusiveSize` 只覆盖前两段：

```
[0,96)        inclusiveSize(要改写) + name[80] + objectId + parentId + flags
[96, inc)     动画轨道（0–3 个）
[inc, inc+8)  geosetId + geosetAnimationId
```

所以「加一个关键帧」= 重建这一条记录、改它自己的 `inclusiveSize`，
其它记录原样拼接。BONE 块的新旧字节替换交给容器层，不用管后续整体移位。

### 两个必须避开的陷阱

**1. 不能按 KGTR→KGRT→KGSC 重排轨道。**
最初 `build_record` 按固定顺序写，结果所有骨骼的字节都变了——
文件里真实的顺序不一定是这个。现在改成**按传入顺序**写，
并且从「解析出来的有序 dict」出发，只替换真正变了的 tag。

**2. 没变结构时不要从曲线重新生成轨道。**
从手柄反算切线会带上 float32 噪声，哪怕用户没碰，字节也会变（实测 35 根骨骼全部偏移）。
现在的规则：结构变化的 tag 用场景数据，其余 tag **直接沿用解析出来的对象**。

### 新关键帧的切线

Hermite/Bezier 轨道插入新键时如果没给切线，用左右邻点的**割线斜率**作为默认值
（单位与文件一致：数值/毫秒），避免出现折角。

### 校验

最硬的一条：**加一个关键帧再删掉，必须逐字节还原原文件**。
11 个模型的 `selftest` 都在跑这条，全部通过。

### 实测

| 操作 | 结果 |
|---|---|
| CLI 插入一个 KGRT 关键帧（Hermite） | +52 字节 = 4 时间 + 16 四元数 + 32 切线 |
| 插入后其它骨骼 | 逐字节不变 |
| Blender 里插一个键再导出 | 只重建该骨骼的记录，BONE 之外不动 |
| Blender 里删一个键再导出 | 同上，关键帧数 −1 |

## 十七、材质与几何动画轨道（B）

### 为什么不能写死偏移

原先按版本门控算图层里轨道的起点（`28 + shader80 + emissive4 + fresnel20`）。
实测 **1000 版模型就比公式短**：轨道起点在 52，而不是 132。

现在改成**末尾锚定的搜索**（`animscan.find_chain`）：

> 从记录起点逐字节找已知 tag，尝试一路解析到**记录的末尾**，
> 第一个能完整吃到末尾的起点就是轨道起点。

这条规则的好处是不依赖任何版本假设：走不通就返回空，绝不给出半对的结果。

### 结构

| 位置 | 轨道区间 |
|---|---|
| 材质图层（MTLS） | `[图层起点+28, 图层末尾)`，1100/1200 的 HD 槽在轨道之前 |
| 几何动画（GEOA） | `[记录起点+28, 记录末尾)` |

### 覆盖与实测

| 项 | 结果 |
|---|---|
| 图层轨道 | 32 条（KMTA 为主，最长 49 帧） |
| 几何动画轨道 | 48 条（KGAO / KGAC） |
| GEOA 记录解析 | 77/77 全部可自证 |
| 改一条 KMTA 数值 | 3,107,066 B 模型只变 **4 字节** |
| 改一条 KGAO 数值 | 1,855,389 B 模型只变 **1 字节** |

```bash
python tools/mdx.py track <file>                                  # 列出全部非节点轨道
python tools/mdx.py track <file> --kind layer --mat 0 --layer 0    # 该图层的轨道
python tools/mdx.py track <file> --kind geoa --record 0            # 该记录的轨道
python tools/mdx.py track <file> --kind geoa --record 0 --tag KGAO --index 2 --value 0.25
```

**限制**：非节点轨道目前只支持**字段级改写**（时间/数值/切线），不支持增删关键帧。
粒子发射器的轨道（KP2*）也走同一套布局，但测试样本里没有，未做实测覆盖。

## 十八、法线导入（C）

### Blender 的存储精度是硬约束

法线写进 Blender 的「自定义分裂法线」后，会被压成 **2×int16 的球面坐标**。
实测解码误差最大 **2.05e-3**（约 0.12°）。

这意味着「拿 Blender 的值和文件的值比较」永远会误判——哪怕用户什么都没动，
也会有几十个顶点"看起来被改了"。

### 解法：导入时记基线

导入时把**解码后**的每顶点法线存进 `mesh["mdx_normals"]`，导出时按基线比对：

- 与基线完全一致 → 没动过，一个字节都不写
- 与基线差异 > 3e-3 → 真的改过，写回

3e-3 这个阈值不是拍脑袋：它高于「整层重新量化」的噪声（实测 2.1e-3），
低于「用户真正拖动一次」的量级。代价是分辨不出小于约 0.2° 的改动——
那本来就低于 Blender 的存储精度。

### 实测

| 项 | 结果 |
|---|---|
| 导入后与文件偏差 | 最大 2.05e-3（即编码精度本身） |
| 不改任何东西 → 导出 | **逐字节相同** |
| 旋转一个法线 30° → 导出 | 只有那个法线的 **12 字节**变 |

### 附带的好处

拓扑编辑（增删顶点）时，法线以场景为准；没有基线时退回「沿用原法线、
新顶点继承最近顶点」，避免把整块几何的着色风格改掉。

## 二十、Blender 体验层：序列 / 贴图 / 导出面板

内核能改，不等于能用。这一步补的是「打开之后看得懂、看得见、知道改没改成功」。

### 1. 动画序列 → 时间轴标记

WC3 的所有动作共用一条时间轴（Stand 在 0–2000 ms，Attack 在 7867–9100 …），
所以导入后整条时间轴有 20 秒却不知道哪段是什么。

现在按 `SEQS` 逐段打 timeline marker，并把区间写进面板：

| 模型 | 序列数 | 标记数 |
|---|---:|---:|
| Lvbu | 30 | 30 |
| David | 10 | 10 |
| BotanistGarden | 6 | 6 |
| kultiranbarracks | 5 | 5 |

帧号 = `毫秒 / 1000 × fps`。面板会根据播放头位置显示「当前：Stand 1（循环，9200–11867 ms）」。

### 2. 贴图

**先修了一个错误**：原先读图层的 `textureId` 前缀字段取贴图，但 1100/1200 的
贴图在图层尾部的合并槽里，前缀是历史字段——实测 David 的 27 个材质全部指到 0 号贴图。
现在优先读 HD 的 Diffuse 槽，材质才各自对上正确的贴图。

路径解析不假设目录结构：

1. 按 TEXS 里的相对路径拼到「贴图目录」下
2. 找不到就**按文件名（去扩展名）**兜底——导出工具常把 `.tif` 存成 `.dds`
3. 还找不到就如实计为「缺失」，不猜

实测（贴图目录 = 模型所在目录）：

| 模型 | 材质 | 载入 | 缺失 | 读不了 |
|---|---:|---:|---:|---:|
| David | 28 | 16 | 12 | 0 |
| kultiranbarracks | 8 | 5 | 3 | 0 |

缺失的都是该目录里没有的文件（引用了别的模型目录下的贴图）。
载入的确实是真图：`David_Helm_Diffuse.dds` 1024×2048、`kultiran_barracks_diffuse.dds`
2048×2048，首像素不是空的。

`.blp`（经典版）明确跳过——它是暴雪私有格式，Blender 读不了，
写了会变成"导入成功但全是灰模"，不如直接报数。

### 3. 导出面板

导出后报告写进场景属性，面板直接显示：

```
上次导出：通过
  移动 1 个顶点；动画改 1 处；3107066 → 3107066 B，3 字节不同
  变化 3 字节
```

以前只能打印到控制台，现在改完一眼就知道"有没有写进去、动了多少字节"。

`check_scene.py` 用**合成贴图**跑全量（故意把 `.png` 起成 `.dds`/`.tif` 的名字，
同时验证扩展名兜底）：
