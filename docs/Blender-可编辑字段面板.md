# Blender 可编辑字段面板（材质 / 贴图路径 / 序列 / 几何动画 / 轴心点）

这一批补的是 Retera 最难用、也最容易出错的部分。核心变化只有一句：

> **改动先落在场景里，导出时才算数。** 每改一处只写 `scene["mdx_state"]`，
> 导出时逐字段与文件比对，只写真正变了的字节，其余一个不动。

好处是随时可以改一半、存 .blend、明天继续；导出前也不会因为误触就毁掉文件。

## 入口

3D 视图右侧边栏 → `MDX` 标签，主面板下五个折叠面板：

| 面板 | 管什么 | 落到哪个 chunk |
|---|---|---|
| 贴图（含一键改路径） | TEXS 的 268 条记录、分类、批量改写 | TEXS |
| 材质与图层 | FilterMode、图层 alpha、Diffuse/Normal/ORM/Emissive/TeamColor/Reflections | MTLS |
| 动画序列 | 起止毫秒、循环、跳转 | SEQS |
| 几何动画 | 整个 geoset 的 alpha 与颜色 | GEOA |
| 轴心点 / 附着点 | PIVT 坐标，挂武器的定位点 | PIVT |

五类字段全是定长，所以改它们**永远不会改变文件长度**，校验只用 `check_delta`
（断言"只有这些字节不同"）就够，不需要放开整块重建。

## 一键改外部贴图路径

这是"合并模型/搬家"最费事的一步，也是 Retera 完全没有的。

点「一键改外部路径…」后：

1. 选方式
   - **统一前缀**：`前缀\文件名`（压平）或 `前缀\原相对路径`
   - **查找替换**：把路径里某段字面换掉（例如 `AF\` → `MyMod\`），其余保持原样
2. 对话框里**实时显示会改几条、改成什么**，看不顺眼可以取消
3. 只有判定为"外部"的条目会被改；游戏内置贴图（`Units\`、`Textures\`、
   `ReplaceableTextures\` 等 27 个根目录）和 replaceableId≠0 的条目一律跳过

判定依据逐条可见，也能人工翻转：面板里点锁图标即可把某条标成"别改我"
（作者自有目录撞上同名游戏目录这种事确实会发生）。

真实数据：11 个测试模型的 367 条贴图里，内置 273 / 外部 84 / 可替换 10。
典型的外部条目是 `AF\Units\Human\David\...`（别人的整合包）和
`kultiran_barracks_Diffuse.dds`（只写文件名、没有目录）。

## 材质面板

按 geoset 归组，每个材质一行标题 + 每层一行。选贴图走**搜索弹窗**
（模型动辄上百张贴图，长下拉列表不可用）。

- 点 FilterMode 按钮 → 7 种模式里选
- 点 `α 0.85` → 滑块改图层 alpha，可勾"同时应用到 geoset alpha"
  （图层 alpha 与 geoset alpha 是两处独立字段，多数情况要一起调才是想要的效果）
- 每个槽位右边两个按钮：放大镜 = 选贴图，图片图标 = 在图像编辑器看大图

HD 模型（1100/1200）的贴图真值在图层尾部的合并槽里，前缀 `textureId` 是历史字段——
面板读的就是槽位。若某个图层的槽后面还跟着动画子块（坐标不可信），
面板会标红，导出时跳过该图层的贴图改动而不是硬写。

## 动画绑定（换掉整套动画）

Retera 没有这个能力，因为它把动画当成模型的一部分，只能整模型替换。

打开 `MDX > 动画绑定`：

1. `检查匹配（不写文件）` —— 先看能对上多少根骨骼，不落盘
2. `绑定到其他模型的动画…` —— 选来源（本地文件 / 游戏数据），确认后执行

来源可以是游戏本体。典型用法：模型 A 现在用的是 footman 的动画，想换成 militia——
填 `units\human\militia\militia.mdx` 即可。

对话框里能看到的：

- **骨骼匹配率**与匹配方式（同名 / 规范化同名 / 层级路径 / 按序号）
- 待搬关键帧数、非零位移关键帧数
- 本模型独有骨骼数（这些骨骼的动画默认保留，不会静默丢数据）

位移轨道三选：照搬 / 跳过 / 按比例缩放。**默认照搬**（忠实），但如果两个模型
尺寸差很多，`KGTR` 是相对父节点的绝对偏移，照搬会错位——报告里会明确提示有
多少条非零位移。

匹配率低于一半会直接警告，一根都没对上会拒绝执行并说明原因，不会硬绑。

**这套操作会直接改写文件**（这是整个插件里唯一这么做的），因为动画轨道和序列表
都是结构会变的块：只改场景状态的话，下次导出会拿 Blender 里那条旧 Action 比对，
把刚绑进来的动画覆盖回去。所以流程是「写盘 → 重新导入」，文件立刻成为新的真相。
改写前自动备份成 `<原名>.mdx.bak`，未导出的其它改动画会丢，对话框里有红字提示。

`解绑本模型动画…` 清空全部关键帧（骨骼保留，蒙皮不受影响）。

## 附着点（挂武器）

`MDX > 附着点（挂武器用）` 列出模型里所有 ATCH：名字、父骨骼、编号、当前挂的模型。

每行四个按钮：

| 按钮 | 作用 |
|---|---|
| 文件夹 | 设置挂载的模型（游戏内路径，如 `war3mapImported\Sword.mdx`；可勾"从本地文件推导"自动生成路径） |
| 光标 | 把 3D 游标移到这个附着点并选中它 —— 摆武器时直接以它为原点 |
| 排序 | 改附着点编号（0–65535，引擎按编号找挂点） |
| 铅笔 | 改名字（视口里的 `ATCH_` 空物体同步改名） |

视口里附着点画成 `SINGLE_ARROW`、尺寸 6 并显示名字，和普通节点（`node_` 前缀的
小十字）区分开。原来"找不到正确附着点"是因为它和几十个 node_ 混在一起、
而且名字根本读不出来（ATCH 的记录比其他节点多一层 size 字段，名字在 +8 而不是 +4）。

实测 71 条 ATCH 记录全部对得上这个布局；修好之后轴心点命名覆盖率从
David 120/144 提到 141/144、Lvbu 201/228 提到 217/228。

### 新增 / 删除附着点

面板底部两个按钮：

- `挂载武器…` —— 选武器（本地文件 / 游戏自带）+ 选附着点，一键写路径。
  选本地文件时会自动复制到模型同级目录并写成 `war3mapImported\文件名`。
- `新增附着点…` —— 填名字、选父节点和**插入位置**（末尾或某个附着点之前）、
  填挂载模型、可选坐标取 3D 游标。

每行还有 `TRASH` 按钮，**可以删任意一条**（不再限末尾）。

#### 中间插删是怎么做对的

删掉第 k 个节点要把后面所有 `objectId` 与 `parentId` 减一，插入则加一。
这需要一张完整的节点表，而早先的解析器认不全（CORN 读不出、PRE2/RIBB 时对时错），
所以只敢在末尾追加。

现在 `chunks/nodes.py` 能把 11 个模型的节点表读全：
**节点数 == 轴心点数、编号严格 0..n-1、无缺失无重复**。两个关键发现：

1. **有一半的节点块是"双重 size"**——记录开头是 `[外层size][Node 自己的 size]`，
   名字在 +8、编号在 +88（ATCH / PRE2 / CORN / RIBB）；另一半是单重，名字 +4（BONE / EVTS / CLID / HELP）。
   按 +4 去读双重块会拿到 `0x00000060` 这种垃圾，这正是以前命名在 120/144 断掉的原因。
2. **CAMS 根本不是节点**——相机没有 objectId/parentId（+84 处直接是坐标浮点），
   也不占轴心点。把它算进节点表会让"节点数 = 轴心点数"永远不成立。

还有一个让实现变简单的性质：**骨骼编号永远小于附着点**（BONE 排最前）。
GEOS 里引用节点编号的只有 `MATS`（矩阵组）和 `SKIN`（蒙皮），引用的都是骨骼。
所以只要增删发生在骨骼之后，**GEOS 一个字节都不用碰**——这条是每次操作前校验的前置条件。

验收：**52 项全过**，其中两条最硬——

- 末尾加一条再删掉 → 逐字节还原
- **中间插一条、再删同一个位置 → 逐字节还原**（会重编号 23–34 处）

外加一条语义断言：删掉一条附着点之后，**其余每个节点的"名字 → 父节点名字"完全不变**。
这条比字节比对更能抓住"编号挪错一位"——那种错字节层面看起来很规整。

## 批量操作

`MDX > 批量操作` 三个功能，**不碰当前打开的场景**，只处理目录：

| 功能 | 做什么 | 安全措施 |
|---|---|---|
| 批量体检 | 每个 mdx 跑「解析 → 重建 → 逐字节比对」，只读 | 不写任何文件 |
| 批量改外部贴图路径 | 统一前缀 / 查找替换，只改判定为外部的条目 | 输出到单独目录、不覆盖原件；每个文件仍过 check_delta |
| 批量解绑动画 | 清空内嵌动画，骨骼与蒙皮不动 | 同上，每个文件过 check_chunk_rewrite |

任一文件失败就跳过它继续下一个，失败原因全部记下来——批量最怕"跑完不知道哪个坏了"。
面板里显示前 12 条，完整结果可打印到控制台。

实测：11 个模型批量体检 **11/11 逐字节一致**；改路径 8 个文件 84 条路径，
逐个复核「长度不变 + 只有 TEXS 变」全过；解绑 8 个文件，逐个复核「只动 BONE 且变短」全过。

## 动画序列 / 几何动画 / 轴心点

### 引擎实测结论（2026-10-17，已通过）

拿 David 做了四组对照（`out/attach-test/`，武器用游戏自带的
`abilities\weapons\axe\axemissile.mdx`，不经过地图 imports）：

| 文件 | 改了什么 | 结果 |
|---|---|---|
| A 原始 | 无 | 无斧子（对照正确） |
| B | 现有点 `Weapon Ref`（父 `weapon_bind_jnt`）的 path | **出现斧子** |
| C | 现有点 `Hand Right Ref`（父 `bone_hand_right`）的 path | **出现斧子** |
| D | 新加一个点（编号 144，父 `bone_hand_right`） | **出现斧子** |

结论两条，都很关键：

1. **ATCH 的 path 在 Reforged 里确实生效**——引擎会在附着点位置渲染该模型，
   并且跟着父骨骼动。所以"挂武器"在模型层面是可行的，不需要依赖地图触发器。
2. **"末尾追加、不重编号"的编号假设成立**——新节点 objectId = 轴心点总数、
   PIVT 追加末尾，引擎照常认。这意味着**不需要节点重编号引擎**，
   想加几个挂点就加几个，每次都追加到末尾即可。

于是"删除中间附着点"这件事的必要性大幅下降：清空 path 的效果与删除等价
（模型里留个空节点，不渲染任何东西、不影响动画）。真要看不过去再上重编号。

## 动画序列 / 几何动画 / 轴心点

- **序列**：改起止毫秒，对话框里同步显示等于第几帧；改完时间轴标记自动刷新
- **几何动画**：整块 geoset 的 alpha 与颜色，这是"隐藏部件"的正规做法
- **轴心点**：默认只列 ATCH（附着点）与 HELP（辅助点）——挂武器真正要动的就是这两个。
  改坐标支持手动输入、取 3D 游标、取选中骨骼头；勾上"同时移动骨骼头"时
  Blender 里的骨骼会跟着动（PIVT 与骨骼头是同一个概念的两处投影）

## 导出报告

导出面板会显示这次动了什么，例如：

```
贴图路径 6 处；FilterMode 1 处、图层 alpha 1 处；2846255 → 2846255 B，273 字节不同
```

字节数应该只等于"被改字段的大小之和"。如果数字对不上，说明有别的地方被动过，
报告里会直接列出越界偏移。

## 自检命令

```bash
# 内核：路径分类 / 改写 / 幂等
python mdx-toolkit/tools/test_paths.py

# 界面注册 + 枚举
blender --background --python blender-addon/check_ui.py -- <model.mdx>

# 端到端：11 模型 × 7 组，断言只有目标 chunk 变

```
