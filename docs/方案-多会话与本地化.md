# 方案：多会话 / 跨模型复制 / 本地化

日期：2026-10-17　适用版本：ModelForge 0.1.x

---

## 一、单文件封装（已完成）

### 结论

`--onefile` 直接打主程序**不可用**：进程能起、服务正常，但 pywebview 窗口永远不出现，
卡在 `webview.start()` 里，无异常无日志。同代码打 onedir 5 秒内正常出窗口。
根因是 onefile 每次运行解压到新的临时目录，WebView2 / .NET 桥接按路径加载托管程序集时对不上。

### 采用方案：自解压启动器

```
ModelForge.exe（外层 19.7 MB，纯标准库，不含 pywebview）
   └─ runtime.zip（内嵌 12.5 MB）
        └─ 首次运行解压到 %LOCALAPPDATA%\ModelForge\runtime\<版本>\
           然后启动里面的 ModelForge.exe
```

外层只做三件事：解压、转发命令行参数、启动。真正跑的是 onedir，所以窗口/CASC/贴图全部正常。
版本号变了会解压到新目录，旧版本不受影响。

实测：首次 2.3 秒完成解压，随后窗口出现；二次启动命中缓存，2 秒出窗口。

命令：`python build.py --single` → `dist/single/ModelForge.exe`

## 二、多会话 + 跨模型复制粘贴

### 现状

后端只有 `App.sess` 一个会话，所有接口默认作用于它。前端一个页面一个模型。

### 改造

**后端**

```python
App.sessions: dict[str, ModelSession]      # sid -> 会话
App.current: str                           # 上次活动的 sid
```

- 所有接口接受可选 `sid`，缺省用 `current`（保持向后兼容，现有测试不用改）
- `POST /api/session/new|close|activate`
- `GET /api/sessions` → 全部会话的简要信息（文件名、脏标记）
- 剪贴板放服务端，跨会话共享：
  - `POST /api/clipboard/copy {sid, kind, indices}` → 返回摘要（复制了什么）
  - `POST /api/clipboard/paste {sid, target}` → 返回插入报告

**前端**

- 顶部标签栏：`David.mdx ● | footman.mdx ● | +`
- `●` 表示有未保存改动
- Ctrl+C / Ctrl+V 走上面的剪贴板
- 关闭有改动的标签时拦一下

### 能复制什么（分四层）

| 层 | 对象 | 需要做的重映射 | 内核现状 |
|---|---|---|---|
| **L1 属性** | 贴图路径、材质参数、序列区间、附着点挂载路径 | 无（纯赋值） | 现有 `edit` 接口已覆盖 |
| **L2 条目** | 附着点、材质、贴图（整条增删） | ATCH 的 objId、MTLS 的 textureId 偏移 | `nodesedit` 已有全表重编号 + PIVT 同步 |
| **L3 几何体** | GEOS + 它的材质 + 贴图 | jnt → 骨骼 id、mat → 材质索引、PIVT | `ops.add_geometry` 已有 |
| **L4 骨骼子树** | BONE/HELP + 父子关系 + 动画轨道 | 节点 id 全表偏移、轨道重编号 | `nodesedit._shift` + `transfer.apply` |
| **L5 动画移植** | 整段动画从 A 套到 B | 骨骼配对、轨道搬运 | **`transfer.py` 已完成并引擎验证过** |

### 建议分期

| 期 | 内容 | 价值 | 风险 |
|---|---|---|---|
| 一期 | 多会话 + L1 + L2 | 换武器、换贴图、搬材质——日常最高频 | 低，都是纯数据 |
| 二期 | L3 几何体 | 真正的"部件移植" | 中，粘贴时骨骼 id 不匹配要处理 |
| 三期 | L4 骨骼子树 | 完整骨架搬移 | 高，PIVT 与骨骼顺序强绑定 |

### 技术难点（如实说）

1. **几何体粘贴时骨骼对不上**。目标模型没有源模型的骨骼 id 时，只有两条路：
   按名字配对（`transfer.match_bones` 已有 L1–L4 兜底）或整棵子树插入。
2. **PIVT 顺序 = 节点顺序**。插入骨骼会让其后所有 id 偏移，涉及 GEOS 的 jnt、
   动画的 KGTR/KGRT/KGSC 索引、ATCH 的 parentId——必须整体重编号，不能只改一处。
3. **动画轨道按节点 id 索引**。这是最容易漏的地方，漏了表现为"动画错乱但不报错"。
4. **粘贴不可逆**。要么做撤销栈，要么每次粘贴前自动存一份副本。

### 建议的一期范围（可在一轮内做完并验证）

- 多会话（标签栏、切换、关闭拦截）
- L1 全量 + L2 的附着点/材质/贴图
- 粘贴前弹确认：`将插入 2 个材质、3 张贴图，索引从 27/88 开始`
- 粘贴后自动标记脏，走现有保存链路
- 引擎验证：A 的武器附着点粘到 B，进游戏确认跟手走

## 三、英文界面与切换

### 机制

- `web/i18n.js`：`const I18N = { zh: {...}, en: {...} }`，扁平 key
- 静态文案：HTML 加 `data-i18n="key"`，启动时按语言替换
- 动态文案：`t("key", {n: 3})`，支持占位符
- 顶栏右侧语言按钮 `中 / EN`，选择存 localStorage
- 首次启动按 `navigator.language` 猜（`zh*` → 中文，其余 → 英文）

### 范围（这是要先定的）

| 范围 | 内容 | 说明 |
|---|---|---|
| A 只做界面 | index.html 约 120 条 + app.js 约 80 条 | 后端报错仍是中文 |
| B 界面 + 错误消息 | 再加 session.py / server.py 约 40 条 | 需要把中文报错改成错误码 |

**B 是破坏性改动**：现在 `SessionError("路径超过 255 字节…")` 直接把中文给人看，
改成 `SessionError("E_PATH_TOO_LONG")` 之后，前端负责翻译，现有测试里断言中文文案的
用例要一起改（`test_server.py` 有若干条）。

### 建议

先做 A（一天量级），后端错误消息保留中文——因为英文用户遇到中文报错的概率远低于
日常操作看界面。等真要发英文版时再做 B。
